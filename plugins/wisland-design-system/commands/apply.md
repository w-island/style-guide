지금부터 **더블유아일랜드 디자인 시스템**을 현재 작업에 전면 적용해줘.

적용 범위: **$ARGUMENTS** (비어 있으면, 방금까지 다루던/현재 열려 있는 UI·화면·컴포넌트 전체)

## 1단계 — 기준부터 모두 읽기
이 플러그인(`wisland-design-system`)의 다음 파일을 먼저 읽고 시작해:
- `SKILL.md` (6대 원칙 + 워크플로)
- `references/tokens.md` (컬러·시맨틱·타이포·그림자·Motion·Breakpoints·A11y + 바로 붙여넣는 CSS `:root` 블록)
- `references/components.md` (버튼·입력·**커스텀 드롭다운**·리스트·뱃지·탭·토글·캘린더·오버레이·테이블·알럿·툴팁·태그칩·아바타·스텝퍼·슬라이더·수량·스크롤바·로고·GNB/LNB 패턴)
- `references/ux-writing.md` (해요체 6원칙 + UX 원칙)

## 2단계 — 범위 내 전수 적용 (빠짐없이)
1. **색**: raw hex/회색 직접 사용을 의미 토큰(`--txt-*`·`--bg-*`·`--border-*`·`--accent`)으로 교체. 토큰이 없으면 `tokens.md`의 `:root` 블록을 추가. 라이트만 맞추면 다크는 자동.
2. **컴포넌트**: 버튼·입력·드롭다운(네이티브 select는 커스텀 드롭다운으로)·리스트·뱃지·탭·토글·캘린더·오버레이·테이블·알럿·툴팁·태그칩·아바타·스텝퍼·슬라이더/수량을 `components.md` 패턴으로 맞춤. 한 화면에 Primary 버튼은 하나.
3. **그림자·라운딩·간격**: 토큰 스케일로. 아이콘은 라인 스타일(둥근 끝).
4. **문구**: 버튼 라벨·안내·에러·빈 화면을 해요체 6원칙으로 다듬기(능동·긍정·쉬운 말). 다이얼로그 왼쪽 버튼은 항상 `닫기`.
5. **다크 모드·접근성**: 대비(본문 4.5:1)·포커스 링·터치 영역 44px·색만으로 정보 전달 금지까지 점검.

## 중요 — 기존 코드 존중
대상 앱에 이미 의미 토큰 시스템이 있으면(예: AI Hub의 `--accent`·`--bg`·`--text-*`), 마크업/클래스를 갈아엎지 말고 **토큰 "값"만 디자인 시스템 팔레트로 리매핑**해. 충돌하는 토큰(특히 액센트)은 먼저 알려주고 진행해. 화면을 JS로 렌더링하는 앱이면 정적 마크업을 끼워넣지 말 것.

## 마무리
무엇을·어디에 적용했는지 요약하고, 디자인 시스템과 안 맞아떨어진 부분은 따로 표시해줘. 가능하면 라이트/다크 둘 다 확인.
